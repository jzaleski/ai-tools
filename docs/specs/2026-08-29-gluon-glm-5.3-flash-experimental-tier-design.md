# Gluon (GLM-5.3-Flash) Experimental Tier (Text-Only)

## Purpose

Add a third experimental-namespace model — `unsloth/GLM-5.3-Flash-GGUF` — as
`jzaleski/experimental/gluon`, text-only for now. Multimodal support for
`gluon` and a backfilled multimodal variant for `boson` (Qwen3.8-Flash-Next)
are intentionally deferred — see "Future Work" below for the documented
longer-term plan, which is *not* implemented by this design.

This is a pattern-matching exercise against the existing `experimental/quark`
/ `experimental/boson` aliases — no new mechanisms, no llama-server changes,
no bootstrap changes.

## Background / Source Material

- Unsloth guide: https://unsloth.ai/docs/models/glm-5.3-flash
- HF repo: https://huggingface.co/unsloth/GLM-5.3-Flash-GGUF
- GLM-5.3-Flash: 320B total / 18B active params, natively multimodal (first
  in the GLM-5 series), hybrid sparse+linear attention, stated max context
  `1,048,576` (1M).
- `UD-Q4_K_XL` quant is split into **6 parts** under a `UD-Q4_K_XL/`
  subdirectory: `GLM-5.3-Flash-UD-Q4_K_XL-00001-of-00006.gguf` through
  `-00006-of-00006.gguf`.
- Root-level `mmproj-F16.gguf` (1.13GB) exists in the repo — noted for the
  deferred multimodal work below, but **not downloaded by this design**
  since there is no alias to use it yet.
- `unsloth/Qwen3.8-Flash-Next-GGUF` (the `boson` model) also has a root-level
  `mmproj-F16.gguf` (904MB) — also noted for deferred work, **not downloaded
  by this design** for the same reason.
- **Caveat (informational, not solved by this design):** Unsloth's guide
  states GLM-5.3-Flash currently requires their llama.cpp fork/PR
  (`unslothai/llama.cpp@glm5next/upstream` or ggml-org PR #27754) — not yet
  merged into mainline llama.cpp, i.e. not yet in the Homebrew `llama.cpp`
  package this repo's `bin/install-dependencies` installs. This design adds
  an informational comment/doc note about this; it does not change bootstrap
  or attempt to vendor a different llama.cpp build.

## Decisions (confirmed via researcher dialogue)

1. **Particle name:** `gluon` (already anticipated as a future particle name
   in the prior dual-router design doc's namespace comment).
2. **Speculative decoding for `gluon`:** **Omitted for now.** Although the
   GGUF's commit metadata (`glm5-next.attention.indexer.index_share_mtp=true`)
   suggests MTP draft tensors may be present, Unsloth's own documented
   `llama-cli` invocation for GLM-5.3-Flash does not pass `--spec-type
   draft-mtp`, and GLM-5.3-Flash support itself is still on an unmerged
   llama.cpp PR. `gluon` runs as plain (non-speculative) inference. A code
   comment documents why, and what would unblock revisiting it (official
   MTP support confirmation for GLM-5.3-Flash upstream).
3. **Sampling profile:** General "Default Settings (Most Tasks)" profile —
   `temp=1.0, top_p=0.95` — not the "DeepSWE" agentic-benchmark profile
   (`temp=0.95, top_p=1.0`), to stay consistent with every other tier in this
   repo (`temp=1.0` throughout). `min-p=0.0` (repo-wide no-op default,
   matching every existing tier except `quark`). `top-k` is **omitted**
   (relying on llama-server's built-in default), mirroring `quark`'s existing
   precedent of omitting flags that don't appear in the vendor's own example
   invocations. `presence-penalty=0.0`, `repeat-penalty=1.0` (repo-wide
   no-op defaults).
4. **Context size:** `1,048,576` (1M) — matches GLM-5.3-Flash's stated
   maximum, same treatment as `quark`.
5. **Reasoning effort:** `"max"` for `gluon` — GLM-5.3-Flash's highest
   available effort (its only options are `low`/`high`/`max`, no
   `medium`/`xhigh`), consistent with every other experimental tier using its
   model's highest available effort (`quark`="high" is DeepSeek's highest;
   `boson`="xhigh" is Qwen3.8's highest).
6. **KV cache / batch / ubatch for `gluon`:** `q8_0`/`q8_0` KV cache,
   `1024`/`256` batch/ubatch — matches `quark`/`boson`'s existing
   experimental-tier tuning (same hardware profile).
7. **Multimodal:** **Deferred.** No `-multimodal` alias, no mmproj download,
   for either `gluon` or `boson`, in this pass. See "Future Work" below for
   the documented plan to implement this later.

## New Alias (Experimental Namespace)

| Alias | Model | Ctx | KV (K/V) | Batch/Ubatch | Spec Decoding | Reasoning Effort |
|---|---|---|---|---|---|---|
| `jzaleski/experimental/quark` (unchanged) | DeepSeek-V4-Flash-0731 | 1,048,576 | q8_0/q8_0 | 1024/256 | DSpark | high |
| `jzaleski/experimental/boson` (unchanged) | Qwen3.8-Flash-Next | 262,144 | q8_0/q8_0 | 1024/256 | MTP | xhigh |
| `jzaleski/experimental/gluon` **(new)** | GLM-5.3-Flash | 1,048,576 | q8_0/q8_0 | 1024/256 | none | max |

Sampling for `gluon`: `temp=1.0, top-p=0.95, min-p=0.0, presence-penalty=0.0,
repeat-penalty=1.0` (no `top-k` — see decision #3). `gluon` keeps the shared
hardware/agentic defaults already applied repo-wide: `flash-attn on`,
`n-gpu-layers -1`, `--reasoning-preserve`, `--cache-reuse 256`,
`--cache-ram -1`, `--load-mode mlock`, `--predict 262144`.

## Testing / Verification Approach

This repo has no automated test suite (shell scripts + config only, per
`AGENTS.md`: "No code repositories - utilities/config only"). Verification
is:

1. `bash -n bin/run-model` and `bash -n bin/run-router` (syntax check).
2. Manual dry-run trace: `bash -x bin/run-model --tier experimental/gluon`,
   confirming the right `llama-server` invocation is constructed (without
   actually requiring the multi-hundred-GB download to succeed — the
   `require_model`/`require_split_model` download step will legitimately
   fail/hang without network access to fetch 200GB+ of weights, so
   verification focuses on argument construction, not an end-to-end model
   load).
3. `sed`-render the updated `llama-cpp-experimental.ini.template` via
   `bin/run-router`'s existing `render_preset` and inspect the rendered INI
   for correctness.
4. `jq` validate `home/.config/opencode/opencode.json` is well-formed JSON
   after edits.
